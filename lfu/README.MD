**LFU** (Least Frequently Used — «наименее часто используемый») — это политика вытеснения из кэша: когда нужно освободить место, удаляем запись с наименьшим числом обращений.

**Контракт.** В этой статье при равном числе обращений используем LRU: вытесняем запись, к которой обращались раньше. Новая запись начинает со счётчика `1`; успешный `Get` и обновляющий `Put` увеличивают его на единицу и обновляют давность. Промах ничего не меняет. При добавлении нового ключа в заполненный кэш сначала вытесняем одну из существующих записей; обновление существующего ключа не требует вытеснения. После удаления и повторной вставки счётчик начинается заново.

Здесь «частота» — накопленное число обращений за время жизни записи в кэше.

Ёмкость должна быть положительной и ограничивает число записей. Например, при ёмкости 2:

| Операция | Счётчики после операции | Результат |
| --- | --- | --- |
| `Put(A, 1)` | A: 1 | Добавили A |
| `Put(B, 2)` | A: 1, B: 1 | A старше B |
| `Get(A)` | A: 2, B: 1 | Вернули 1 |
| `Get(B)` | A: 2, B: 2 | При равной частоте A старше B |
| `Put(C, 3)` | B: 2, C: 1 | Вытеснили A по правилу LRU |
| `Put(D, 4)` | B: 2, D: 1 | Вытеснили C как наименее часто используемую запись |

## Базовая реализация: поиск жертвы перебором

Частоту и номер последнего обращения храним в записи. При вытеснении перебираем таблицу и выбираем минимальную пару `(frequency, stamp)`: сначала сравниваем частоту, затем давность. `stamp` — логический счётчик операций, а не физическое время.

**Псевдокод**

```text
ОБЪЕКТ LFUCache(capacity > 0):
    items ← таблица «ключ → (value, frequency, stamp)»
    clock ← 0

    МЕТОД Get(key):
        ЕСЛИ key отсутствует в items: ВЕРНУТЬ (НЕТ, ЛОЖЬ)
        clock ← clock + 1
        items[key].frequency ← items[key].frequency + 1
        items[key].stamp ← clock
        ВЕРНУТЬ (items[key].value, ИСТИНА)

    МЕТОД Put(key, value):
        frequency ← 0
        ЕСЛИ key есть в items:
            frequency ← items[key].frequency
        ИНАЧЕ ЕСЛИ размер(items) = capacity:
            victim ← ключ с минимальной парой (frequency, stamp)
            удалить items[victim]                 # полный перебор: O(n)
        clock ← clock + 1
        items[key] ← (value, frequency + 1, clock)
```

Ниже два самостоятельных примера:

```go
type LFUCache struct {
	cap, clock int
	items      map[string]*lfuItem
}

type lfuItem struct {
	val              any
	frequency, stamp int
}

func NewLFUCache(cap int) *LFUCache {
	if cap <= 0 {
		panic("capacity must be positive")
	}
	return &LFUCache{cap: cap, items: make(map[string]*lfuItem)}
}

func (c *LFUCache) Get(key string) (any, bool) {
	val, ok := c.items[key]
	if !ok {
		return nil, false
	}

	c.clock++
	val.frequency++
	val.stamp = c.clock

	return val.val, true
}

func (c *LFUCache) Put(key string, val any) {
	v, ok := c.items[key]
	if ok {
		c.clock++
		v.frequency++
		v.stamp = c.clock
		v.val = val

		return
	}

	c.evictIfFull()

	c.clock++
	c.items[key] = &lfuItem{
		val:       val,
		frequency: 1,
		stamp:     c.clock,
	}
}

func (c *LFUCache) evictIfFull() {
	if len(c.items) < c.cap {
		return
	}
	victim, first := "", true
	var best *lfuItem
	for key, item := range c.items {
		if first || item.frequency < best.frequency ||
			(item.frequency == best.frequency && item.stamp < best.stamp) {
			victim, best, first = key, item, false
		}
	}
	delete(c.items, victim)
}
```

Пусть `n` — текущее число записей, `C` — ёмкость кэша. Оценки относятся к обычной работе хеш-таблицы: доступ ожидаемо `O(1)`, вставка — ожидаемо амортизированно `O(1)`.

| Операция                              | Сложность                       | Причина                                          |
| ------------------------------------- | ------------------------------- | ------------------------------------------------ |
| `Get`: попадание или промах           | Ожидаемо `O(1)`                 | Поиск в map и обновление счётчиков при попадании |
| `Put`: обновление существующего ключа | Ожидаемо `O(1)`                 | Запись уже найдена, вытеснение не нужно          |
| `Put`: новый ключ при наличии места   | Ожидаемо амортизированно `O(1)` | Добавление в map                                 |
| `Put`: новый ключ в заполненный кэш   | `O(n)`                          | Полный перебор при выборе жертвы                 |
| Выбор и удаление жертвы               | `O(n)`                          | Сравнение пар `(frequency, stamp)`               |
| Память при заполнении                 | `O(C)`                          | До `C` записей и их метаданные                   |

У этой реализации два ограничения: она не потокобезопасна, а вставка в заполненный кэш требует линейного перебора. Без внешней синхронизации её можно использовать только из одной горутины.

## Можно ли ускорить вытеснение кучей?

Первым вариантом могла бы стать минимальная куча по паре `(frequency, stamp)`. 
В такой реализации успешный `Get` и обновляющий `Put` требуют восстановления кучи через `heap.Fix` за `O(log n)`. Вставка нового ключа и вытеснение также занимают `O(log n)`: при заполненном кэше удаление минимума и добавление новой записи вместе всё ещё дают `O(log n)`. Промах `Get` остаётся ожидаемо `O(1)`. Таким образом, вставка в заполненный кэш ускоряется с `O(n)` до `O(log n)`, но успешные чтения и остальные варианты `Put` становятся дороже. Эти оценки следуют из [контракта операций `container/heap`](https://pkg.go.dev/container/heap).

## Группы частот: Get и Put за ожидаемое O(1)

Можно воспользоваться тем, что при каждом обращении счётчик увеличивается ровно на единицу. Вместо общей кучи заведём:

- `items`: map из ключа в узел двусвязного списка.
- `order`: map из частоты в список записей с этой частотой.
- `minFreq`: минимальную частоту среди текущих записей.

Внутри каждой группы начало списка соответствует самому недавнему обращению, конец — самому давнему. Поэтому жертва находится в конце списка `order[minFreq]`.

При обращении переносим запись из группы `f` в начало группы `f+1`. Если старая группа опустела, удаляем её. Если она была минимальной, новая минимальная частота равна `f+1`: перемещаемая запись гарантированно окажется в этой группе, а меньших частот уже нет. После добавления нового ключа устанавливаем `minFreq = 1`.

Инварианты после каждой публичной операции: каждый ключ есть ровно в одном списке и в `items`; частота записи совпадает с ключом её группы; пустые группы отсутствуют; у непустого кэша `minFreq` указывает на минимальную группу, у пустого равен нулю.

Все публичные методы защищаем одним `Mutex`. Успешный `Get` меняет счётчик и списки, поэтому ему тоже нужна эксклюзивная блокировка. Мьютекс защищает структуры кэша, но не изменяемые объекты, возвращаемые через `any`: их использование вызывающий код синхронизирует самостоятельно. 

```go
import (
	"container/list"
	"sync"
)

type LFUCache struct {
	mu      sync.Mutex
	cap     int
	items   map[string]*list.Element
	order   map[int]*list.List
	minFreq int
}

type lfuItem struct {
	key       string
	val       any
	frequency int
}

func NewLFUCache(cap int) *LFUCache {
	if cap <= 0 {
		panic("capacity must be positive")
	}
	return &LFUCache{cap: cap, items: make(map[string]*list.Element), order: make(map[int]*list.List)}
}

func (c *LFUCache) Get(key string) (any, bool) {
	c.mu.Lock()
	defer c.mu.Unlock()

	val, ok := c.items[key]
	if !ok {
		return nil, false
	}
	item := val.Value.(*lfuItem)

	c.touch(val)

	return item.val, true
}

func (c *LFUCache) Put(key string, val any) {
	c.mu.Lock()
	defer c.mu.Unlock()

	el, ok := c.items[key]

	if ok {
		v := el.Value.(*lfuItem)
		v.val = val
		c.touch(el)

		return
	}

	if len(c.items) >= c.cap {
		c.evict()
	}

	if c.order[1] == nil {
		c.order[1] = list.New()
	}

	c.items[key] = c.order[1].PushFront(&lfuItem{val: val, frequency: 1, key: key})
	c.minFreq = 1
}

func (c *LFUCache) Delete(key string) bool {
	c.mu.Lock()
	defer c.mu.Unlock()

	el, ok := c.items[key]
	if !ok {
		return false
	}

	item := el.Value.(*lfuItem)
	freq := item.frequency

	l := c.order[freq]
	l.Remove(el)

	// Удаляем из map.
	delete(c.items, key)

	if l.Len() == 0 {
		delete(c.order, freq)

		if c.minFreq == freq {
			c.minFreq = 0

			// После Delete следующая частота может быть любой: нужен поиск.
			for f := range c.order {
				if c.minFreq == 0 || f < c.minFreq {
					c.minFreq = f
				}
			}
		}
	}

	return true
}

// Вызывается под mu только из Put для заполненного кэша.
// До освобождения mu Put вставит запись с частотой 1 и обновит minFreq.
func (c *LFUCache) evict() {
	minList := c.order[c.minFreq]
	minEl := minList.Back()
	minList.Remove(minEl)

	if minList.Len() == 0 {
		delete(c.order, c.minFreq)
	}

	delete(c.items, minEl.Value.(*lfuItem).key)
}

// Вызывается только под mu. Переносит запись из группы f в f+1.
func (c *LFUCache) touch(item *list.Element) {
	el := item.Value.(*lfuItem)
	oldList := c.order[el.frequency]
	oldList.Remove(item)

	if oldList.Len() == 0 {
		delete(c.order, el.frequency)

		if c.minFreq == el.frequency {
			// Перемещаемая запись гарантированно создаст непустую группу f+1.
			c.minFreq++
		}
	}

	el.frequency++

	if c.order[el.frequency] == nil {
		c.order[el.frequency] = list.New()
	}

	newItem := c.order[el.frequency].PushFront(el)
	c.items[el.key] = newItem
}
```

Пусть `b` — число непустых групп частот; `b <= n`. Для этого варианта сложность следующая:

| Операция | Сложность | Причина |
| --- | --- | --- |
| `Get`: промах | Ожидаемо `O(1)` | Поиск в map |
| `Get`: попадание | Ожидаемо амортизированно `O(1)` | Перенос между двумя известными группами |
| `Put`: обновление, вставка со свободным местом или с вытеснением | Ожидаемо амортизированно `O(1)` | Известная жертва и постоянное число операций с map и списками |
| Вытеснение внутри `Put` | Ожидаемо `O(1)` | Удаление последнего узла минимальной группы |
| `Delete`: промах, удаление не последнего узла группы или последнего узла неминимальной группы | Ожидаемо `O(1)` | Следующую минимальную частоту искать не нужно |
| `Delete`: удаление последнего узла минимальной группы | `O(b)` по оставшимся группам; до `O(n)` | Поиск нового минимума перебором `order` |
| Память при заполнении | `O(C)` | До `C` записей и до `C` непустых групп |

Для пустого остатка кэша `Delete` занимает `O(1)`; точная общая оценка ветки поиска — `O(1 + b)`. Оценки не включают ожидание мьютекса: постоянная алгоритмическая сложность не гарантирует постоянную задержку при конкурентной нагрузке.

## Почему Delete сложнее и как его ускорить

После удаления последнего узла минимальной группы нельзя просто увеличить `minFreq`: следующая группа может иметь любую частоту. Например, если существуют группы 1 и 100, удаление единственной записи из группы 1 должно установить `minFreq = 100`. Поэтому здесь приходится перебирать `order`.

Для ожидаемого `O(1)` и у `Delete` можно хранить сами группы в двусвязном списке, отсортированном по возрастанию частот. Каждая запись дополнительно знает свою группу, а каждая группа содержит собственный список записей в порядке LRU.

При обращении к записи из группы `f` проверяем следующую группу. Если её частота равна `f+1`, переносим запись туда; иначе создаём группу `f+1` непосредственно после текущей. Пустую группу удаляем. Минимальная группа всегда находится в голове внешнего списка, поэтому после `Delete` не нужен поиск: следующая группа уже доступна по указателю. Новую запись добавляем в группу 1 в начале списка, создавая её при необходимости.

Структурные операции со списками здесь занимают `O(1)`, а оценка публичных методов остаётся ожидаемой из-за хеш-таблицы. Отдельный пример реализации: [LFU со списком групп частот](https://github.com/Aneg/alg/blob/main/lfu/delete/main.go).

## Ограничения и дальнейшие доработки

Накопительные счётчики плохо забывают прошлую популярность. Запись, которую когда-то читали очень часто, может надолго остаться в кэше, даже если теперь почти не нужна. Можно добавить старение счётчиков, но это изменит политику: деление или уменьшение частот может потребовать объединения групп и восстановления порядка. Сложность такой процедуры нужно учитывать отдельно.

В учебных примерах `frequency` и `clock` имеют тип `int`; переполнение не обработано. Корректность предполагает, что счётчики не выходят за диапазон типа. Для долгоживущего кэша нужно отдельно определить поведение при достижении предела. Переход на `uint64` увеличит диапазон, но не устранит проблему принципиально; ограничение счётчика сверху или старение изменят точный накопительный LFU.

TTL — отдельная политика срока жизни, её можно сочетать с LFU. Нужно определить, продлевает ли срок `Get` или только `Put`, проверять срок при чтении и удалять просроченную запись из всех структур. В текущей реализации удаление последней записи минимальной группы может потребовать поиска за `O(b)`, поэтому добавление TTL не сохраняет все оценки автоматически. Если использовать отдельную кучу сроков, появится и стоимость операций с ней.

## Заключение

Перебор даёт простую реализацию LFU, но делает вставку в заполненный кэш линейной. Группы частот позволяют выполнять `Get` и `Put` за ожидаемое амортизированное `O(1)`, сохраняя LRU при равных счётчиках. Двусвязный список самих групп устраняет линейный поиск и из `Delete`. При добавлении TTL, старения и конкурентного доступа важно заново проверять как гарантии, так и стоимость операций.
